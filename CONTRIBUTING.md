# Contributing to Awesome Built-in AI
We love pull requests! To keep this repository as a high-quality, premier reference for developers, please follow these guidelines.

## Submission Rules
1. **Quality Over Quantity:** We only accept working, high-quality projects or highly informative educational content. Avoid submitting low-effort, broken, or duplicate examples.
2. **Chronological Accuracy:** For articles, talks, or milestone updates, please prepend the date in `YYYY.MM` format as seen in the README.
3. **Specify Requirements:** If your project requires a specific environment or custom flag configuration, explicitly state it in your description.
4. **Lifecycle & Recency (Apps/Tools):** Live code implementations feature an '[As of: YYYY.MM]' timestamp to log when they were last verified. Entries are kept on a rolling 12-month window. Maintainers or authors can submit a quick PR to update this timestamp if the implementation remains fully compliant with native browser APIs.

## Formatting Standard
Please format your markdown entries precisely like this:
```markdown
* [Project Name](URL) - A crisp, single-sentence description of the project focused on answering “So, what?”. [As of: YYYY.MM]
```

## Step-by-Step Process
1. Fork this repository.
2. Create your branch (`git checkout -b feature/amazing-resource`).
3. Add your resource to the bottom of the most relevant category.
4. Commit your changes (`git commit -m 'Add awesome local AI tool'`).
5. Push to the branch (`git push origin feature/amazing-resource`).
6. Open a Pull Request.
